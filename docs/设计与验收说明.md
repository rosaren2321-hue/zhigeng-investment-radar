# 知更 · 投资风险雷达

## 产品定位

面向有明确关注标的、但无法持续盯盘的个人投资者，将一句关注点转成可检查、可修改、持续运行的规则。核心交付是信息监控，不是投资建议或交易执行。

本次候选人作品采用明确标注的合成数据，便于评审重复验证命中、未命中、数据过期、冲突、失败与恢复。没有取得扶摇或 iFinD 数据权限前，不将演示值包装成实时行情。

## 主链路

1. 输入关注点。DeepSeek 提取标的、条件、条件关系、检查间隔与冷却时长。
2. 规则确认。用户看到明确的标的代码、字段、比较符与阈值，并能直接修改。含糊表达先追问，不静默设置关键价格阈值。
3. 保存并启动。规则持久保存；每个版本有独立快照与修改说明。
4. 定时检查。调度与页面是否打开分离；记录检查时间、规则版本、数据快照、结果和下一次检查。
5. 解释结果。区分未命中、已提醒、重复快照、冷却抑制和无法判断。
6. 查看证据。展示来源、数据时间、采集时间、当前值、比较条件与逐条判断。
7. 故障恢复。失败后退避重试；恢复后重新检查，并保留此前的未知状态。绝不把过期值当成最新值。

## 设计取舍

- AI 负责将自然语言变成规则草案，不直接决定是否触发提醒；触发由可测试的确定性执行器判断。
- 价格、日内涨跌幅、事件关键词、日历提前天数、热度阈值使用统一条件结构，支持全部满足／任一满足。
- 组合条件采用保守数据策略：任何必需数据未知时，本轮整体无法判断，避免用缺失数据拼接确定结论。界面必须显示是哪条证据不足。
- 同一规则版本、同一证据不重复提醒；不同证据仍受到冷却期限制。编辑规则后重新评估，保留旧版本审计记录。
- 提醒落在站内记录，不发送真实交易指令，不假装已向微信、短信或邮箱送达。
- 演示环境全天可检查；不使用简单工作日判断冒充 A 股交易日历。
- 定时器心跳与任务检查结果分别显示。没有运行凭证时标记未接通或延迟，不用绿色状态掩盖调度故障。

## 数据与模型边界

- DeepSeek 官方接口：`https://api.deepseek.com/chat/completions`。
- 当前官方入门文档与 JSON 输出示例使用 `deepseek-flash`；模型名可在服务端配置。
- JSON 模式只能约束输出格式，仍需服务端校验字段、类型、边界和支持的标的。
- 无密钥、超时或格式错误时，明确显示备用解析器；不能宣称成功调用了模型。
- 模型输入仅包含用户关注点和规则协议，不包含 API 密钥、账户资产或个人交易记录。

参考：[DeepSeek 接口文档](https://api-docs.deepseek.com/)、[JSON 输出](https://api-docs.deepseek.com/guides/json_mode)。查阅日期：2026-10-07。

## 验收清单

| 要求 | 可操作的验收方法 |
|---|---|
| 自然语言转可修改规则 | 输入明确的价格关注点，核对阈值；改阈值并保存 |
| 统一条件模型 | 分别创建价格、事件、日历、热度与组合任务 |
| 调度与状态 | 关闭页面后由后台调度检查，重新打开看到运行记录 |
| 去重与冷却 | 对同一快照重复检查，再用不同快照在冷却期检查 |
| 失败与恢复 | 注入接口失败，再恢复数据；查看两轮原因和恢复标识 |
| 版本变化 | 编辑规则后查看版本历史和新旧检查所用版本 |
| 过期与冲突 | 注入相应场景，确认“无法判断”且没有误报 |
| 结论可追溯 | 从提醒回到本次运行证据和规则版本 |
| 合规边界 | 输入交易执行、收益保证等要求，确认拒绝执行 |
| 持久化与隔离 | 刷新／重新打开保留数据；其他浏览器空间不能读取任务 |
| AI 验证 | 保存模型／提示词版本、生成模式、错误分类及测试记录 |

测试结果、可访问地址和录屏链接以完成后的交付索引为准。
