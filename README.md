# 知更 · 投资风险雷达

把自然语言关注点转换为可检查、可修改、持续运行的监控任务；每次触发或未触发都能查到规则版本与数据证据。

> **本项目目前使用明确标注的合成演示数据。** 不代表实时股票价格、真实公告、市场热度或实际财报日历。未取得扶摇 / iFinD 的访问权限，不假称已接通。

## 目标用户与核心设计

面向已有明确关注标的、无法持续盯盘的个人投资者。核心路径是“输入关注点 → 确认并修改规则 → 持久保存 → 后台检查 → 去重/冷却 → 站内提醒与证据追溯”。

- **统一任务模型**：价格、日内涨跌幅、公告标题关键词、财报日历提前天数、0–100 热度，支持全部满足或任一满足；每个任务一个标的、最多 5 个条件。
- **规则版本**：每次编辑创建新版本，旧版检查与提醒继续可查；可以把旧版作为新草案编辑。过期版本修改返回 409。
- **运行状态**：未命中、已提醒、去重、冷却、无法判断、暂停和到期分别展示。
- **未知不等于未命中**：过期、冲突、缺失、无效数值、未来时间戳、错误标的或接口失败均暂停判断；不会基于可疑数据提醒。组合规则采用保守策略：任一所需证据未知，整体未知，即使另一个 OR 条件已满足。
- **去重与冷却**：去重键为任务 + 规则版本 + 证据指纹；公告使用事件 ID，不用采集时间，避免同公告每轮重报。去重优先于冷却；新证据在冷却期内仅记录检查。
- **恢复**：数据异常后按 1/2/4/8…分钟退避，最多 60 分钟。恢复后重新计算并标记恢复，不重建不确定期间的历史判断。
- **并发与持久化**：Cloudflare D1 保存任务、版本、检查、提醒和 AI 记录；数据库租约串行化单任务检查，事务保存检查及提醒，唯一约束防重复；修改与版本快照在同一事务中。
- **空间隔离**：已登录用户使用平台注入的身份；匿名访客使用不可猜测的 HttpOnly 会话 Cookie。服务端按 owner 检查权限，写入校验 Origin；密钥不进入前端。

## AI 的角色与验证

DeepSeek 仅把用户文本编译为待确认规则，不执行交易、启动任务或判断行情。使用官方 `/chat/completions` 接口、JSON 输出与服务端规则校验。提示词版本为 `rule-compiler-v1.0`；模型名默认 `deepseek-flash`，以配置为准。

用户必须检查并确认草案。缺失阈值、含糊单位、多标的、未支持指标或时段需要澄清。模型超时、HTTP 错误、空输出、无效 JSON 或字段校验失败时降级到明确标注的有限模板；不冒充模型调用成功。

每次解析保存生成模式、模型、提示词版本、澄清问题、警告和结果。模型返回的 token 用量保留在记录中。每天每空间最多 30 次解析请求，整个演示最多 200 次。当前验证结果见 `docs/`，模拟接口测试与真实模型测试分别记录。

官方文档（2026-10-07 核对）：[接口](https://api-docs.deepseek.com/) · [JSON 输出](https://api-docs.deepseek.com/guides/json_mode)。

## 数据使用与可追溯性

`lib/radar/engine.ts` 中 `demoSnapshot` 生成确定性演示数据：行情以 5 分钟快照分桶，公告以单日稳定事件 ID 去重，财报日历是相对当前日期的合成事件。每个快照记录 `source`、`sourceUrl`、`observedAt`、`fetchedAt`、标的、数据质量和具体值。

`demo://fixtures/v1` 是项目内演示来源标识，并非交易所或行情供应商地址。界面提供正常、命中、未命中、过期、冲突和失败场景，主动切换后，后台也继续使用该场景，直至手动切回正常。

接入扶摇或 iFinD 时，应新增经过契约测试的服务端数据适配器，映射到 `Snapshot` 协议，并保留官方来源、数据时间、交易日历和授权范围；不能简单删除“演示数据”标识。当前产品没有实现/声称真实供应商适配器。

## 后台调度

`.github/workflows/monitor.yml` 每 5 分钟请求受密钥保护的 `POST /api/cron`；页面每 15 秒仅刷新显示。后端持久保存每条任务的计划时间，扫描到期任务（单轮最多 50 条），并写入调度心跳。页面关闭后仍能被外部定时器检查。

GitHub Actions 定时执行可能延迟，因此不保证准点或硬实时。检查间隔为期望的最短间隔；异常重试计划最终也受调度粒度限制。超过 15 分钟未收到心跳，界面显示延迟。演示任务运行 7 天后自动到期，用户恢复可延长 7 天。没有心跳凭证时不显示“已正常运行”。

仓库 Secrets：`RADAR_SITE_URL`、`RADAR_CRON_SECRET`，私有 Sites 还需 `RADAR_SITE_BYPASS`。服务端 Secrets：`CRON_SECRET`、`DEEPSEEK_API_KEY`。两个 cron secret 必须相同。

## 本地运行

需要 Node.js ≥ 22.13（建议 24）与 npm。

```sh
npm ci
cp .env.example .env.local
# 在 .env.local 中填入 DEEPSEEK_API_KEY；不配置也可验证备用解析与所有监控流程
npm run db:generate # 只有修改 schema 时才生成新迁移；现有迁移已随源码提供
npm run build
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_brainy_johnny_blaze.sql
npm run dev
```

只对空的本地数据库应用已有迁移一次。修改 schema 时生成并检查新的追加迁移，不覆盖已发布迁移。开发访问服务打印的地址（默认 `http://127.0.0.1:5173`）。

## 已知边界与未做事项

- 未接入真实行情、公告、市场热度、交易日历或组合持仓；不提供真实金融结论。
- 全天按分钟监控；没有用“周一到周五”冒充 A 股交易日历；不支持开闭市窗口或连续时长条件。
- 价格条件是当前阈值判断，“跌破/突破”不表示已经验证穿越轨迹。
- 公告按标题字面匹配，未实现正文语义分析；财报提前天数按 24 小时向上取整。
- 仅站内提醒，没有短信、邮件、微信推送或外部投递回执。
- 匿名空间通过当前浏览器凭证访问；清除凭证后不能找回，未做跨设备登录管理。
- 单任务最多 5 条条件，单空间最多 20 个任务；运行记录页面显示最近 60 条、提醒最近 100 条。导出同样保留这些展示上限，累计计数使用数据库全量统计。
- 演示没有实施长期归档和删除策略；大量访客或长期生产运行需增加保留周期、全局任务配额和告警投递机制。
- WebMCP 是渐进增强：在提供 `document.modelContext` 的浏览器中注册“准备监控关注点”工具，不会自动创建任务；普通浏览器不依赖它。
- 不执行交易、不承诺收益、不提供仓位建议。合规边界为产品权限设计，不是对任何监管资质的认证。
